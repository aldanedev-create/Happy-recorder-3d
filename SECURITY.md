| Version | Supported          |

## Reporting a Vulnerability

We take security seriously at Happy Recorder 3D. If you discover a security vulnerability, please follow these steps:

### Do NOT:
- Report vulnerabilities in public GitHub issues
- Disclose the vulnerability publicly before it's fixed
- Share the vulnerability with others before it's resolved

### DO:
1. **Email us**: Send a detailed report to `aldanehutchinson5@gmail.com`
2. **Include**:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if available)
3. **Wait for response**: We'll acknowledge receipt within 48 hours
4. **Follow up**: We'll provide updates on the fix progress

### Security Response Timeline

| Step | Timeline |
|------|----------|
| Initial Response | Within 48 hours |
| Vulnerability Triage | Within 5 days |
| Fix Development | Based on severity |
| Patch Release | As soon as possible |
| Public Disclosure | After fix is released |

## Security Features

### Application Security
- No artificial recording-time limits
- Local storage only - no cloud uploads without user consent
- No telemetry or tracking without explicit opt-in
- Open source for transparency

### Best Practices
- All dependencies are regularly updated
- Security patches applied promptly
- Code reviewed for vulnerabilities
- Built-in permissions management

## Responsible Disclosure

We believe in responsible disclosure and appreciate the security community's efforts to make software safer. We will:

- Credit reporters (if desired)
- Release fixes promptly
- Document security improvements
- Reward significant contributions
